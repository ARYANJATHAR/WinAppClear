# Your final five steps

Preparation files and the unsigned MSI candidate are local. Do not submit the unsigned candidate. Microsoft decides certification; these files are not a certification result.

1. **Create/verify your Microsoft Store developer account and reserve WinAppClear.** Use https://storedeveloper.microsoft.com and create an **EXE or MSI app** in Partner Center. Complete identity checks yourself. Use the publisher identity you verify there. If the name is unavailable, update branding before submission.

2. **Obtain a trusted code-signing identity and make the final signed build.** Use a CA-trusted code-signing certificate/provider available to you. Install its private-key provider and Windows SDK Signing Tools. Do not send anyone your private key or password. From the repository root run `./scripts/Build-Store.ps1 -CertificateThumbprint YOUR_CERTIFICATE_THUMBPRINT -OutputDirectory artifacts/store-signed`. For a hardware token, authenticate when its provider prompts. The script signs the app before embedding it, then signs the MSI, verifies signatures and writes checksums. Supply `-SignToolPath` if needed. If using a remote signing service instead, sign the app before packaging and the MSI afterward, then run the verification gate with `-RequireSignature`. A self-signed certificate is not a Store signing identity. Never sign or replace the payload after packaging it.

3. **Validate the signed release in clean Windows VMs.** Windows 10 and Windows 11 x64: run `scripts/Test-StoreInstall.ps1` as administrator in a disposable VM, using the signed MSI and optionally a previous signed MSI for upgrade testing. It installs, repairs, starts the app with isolated data, checks retained user data, and uninstalls only WinAppClear. Then complete `VM-VALIDATION.md`, including a real harmless fixture's uninstall/leftover/backup/restore and manual installation recording. Do not submit until the relevant checks pass. The development machine has no Windows Sandbox or available VM, so those results are pending, not assumed.

4. **Publish the exact signed installer and public documents.** Push the reviewed source/docs to your repository, make a version-specific GitHub release (for example `v0.1.4`) and upload the signed MSI, SHA256SUMS.txt and notices. Use a fixed direct URL such as `https://github.com/ARYANJATHAR/WinAppClear/releases/download/v0.1.4/WinAppClear-0.1.4-win-x64.msi`. Verify an anonymous download and the SHA-256. Publish and open the privacy-policy URL from LISTING.md. Once submitted, never overwrite that installer asset; issue a new version and URL for changes. Rebuilding/signing changes hashes, so use the signed build's checksum.

5. **Complete the Store listing and submit for review.** Paste LISTING.md's copy, upload the actual-interface images and logo, provide the verified privacy/support links, complete pricing/markets and age-rating questions, and configure the MSI package with x64, English and System/per-machine scope where requested. Select MSI: Microsoft Store applies its default `/qn` silent switch automatically (the manual test command also adds `/norestart`). Provide the exact versioned installer URL; custom installer-parameter/return-code fields generally apply to EXE submissions, so retain standard MSI handling. Paste the certification notes, review all fields and submit. Resolve any review feedback before publication. Do not describe the animated video as a live recording.

Official references: [MSI/EXE requirements](https://learn.microsoft.com/en-us/windows/apps/publish/publish-your-app/msi/app-package-requirements), [package fields](https://learn.microsoft.com/en-us/windows/apps/publish/publish-your-app/msi/upload-app-packages), [developer account](https://learn.microsoft.com/en-us/windows/apps/publish/faq/open-developer-account).
